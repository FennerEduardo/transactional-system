# transactional-system

Reference project for [gherkin-ai](https://github.com/FennerEduardo/gherkin-ai-cli) 3.2.1. Baseline reference: an ASP.NET Core 8 service following CQRS, with RabbitMQ messaging, generated from a single transactional feature. It is the project the other references are compared against.

The project at the repository root was generated by `ghk generate` from the specification in `features/transactional-system.feature`. The project builds, and its generated tests and runtime integration suite pass, as verified on 2026-10-30 (see [Verification](#verification)).

## Stack

| Part | Technology |
|---|---|
| Backend | ASP.NET Core 8 (C#, Npgsql) |
| Runtime kernel | PostgreSQL command service with idempotency and transactional outbox, outbox relay and inbox consumer with dead-letter queue over RabbitMQ (default), Google Cloud Pub/Sub or Azure Service Bus, saga orchestrator, OpenTelemetry trace propagation |
| Application layer | `POST /api/v1/<feature>/{id}/{command}` on the runtime command service; the tenant comes only from the validated JWT (`tenant_id` claim) |
| Architecture (configuration) | `cqrs` |

## Specification

**Transactional System** (`features/transactional-system.feature`)

> As a system user or business manager
> I want to process and manage transactional system operations
> So that data integrity and business rules are enforced across the application

Scenarios:

1. Process transactional system successfully
2. Reject transactional system with invalid parameters

## Build and test

The commands below are the ones gherkin-ai uses to verify this stack. Run them from the repository root with the toolchain installed, or inside the official image `mcr.microsoft.com/dotnet/sdk:8.0`.

```bash
dotnet build tests/*/*.Tests.csproj -nologo -v q
dotnet test tests/*/*.Tests.csproj -nologo -v q --no-build --filter "Category!=Integration&Category!=Testcontainers"
```

Runtime integration suite (IT1–IT7: transactional outbox, idempotency under concurrency, exactly-once relay, tenant isolation, saga compensation, inbox deduplication and dead-lettering, trace propagation), plus an HTTP test of the generated API (tenant from the JWT, idempotency key, outbox):

```bash
docker run -d --name ghk-pg -e POSTGRES_PASSWORD=ghk -p 5432:5432 postgres:17-alpine
docker run -d --name ghk-mq -e RABBITMQ_DEFAULT_USER=ghk -e RABBITMQ_DEFAULT_PASS=ghk -p 5672:5672 rabbitmq:4-alpine
export DATABASE_URL=postgres://postgres:ghk@localhost:5432/postgres AMQP_URL=amqp://ghk:ghk@localhost:5672
dotnet test tests/*/*.Tests.csproj -nologo --no-build --filter "Category=Integration" --logger "console;verbosity=normal"
```

The same suite runs against the Google Cloud Pub/Sub emulator. The gherkin-ai golden `dotnet-pubsub` verifies this runtime's Pub/Sub adapter, and `dotnet-servicebus` its Service Bus adapter against the official emulator:

```bash
docker run -d --name ghk-pubsub -p 8085:8085 gcr.io/google.com/cloudsdktool/google-cloud-cli:emulators \
  gcloud beta emulators pubsub start --host-port=0.0.0.0:8085 --project=local-project
export GHK_BROKER=pubsub PUBSUB_EMULATOR_HOST=localhost:8085 PUBSUB_PROJECT_ID=local-project
dotnet test tests/*/*.Tests.csproj -nologo --no-build --filter "Category=Integration" --logger "console;verbosity=normal"
```

AWS CDK app (`infrastructure`, image `node:24-bookworm`), offline, no AWS account needed:

cd infrastructure

## Production image and cloud deployment

The repository root has a production `Dockerfile` (multi-stage, non-root user) and a `.dockerignore`. The image is configured only through environment variables, so the same image runs on AWS ECS Fargate, Google Cloud Run, Azure Container Apps or Kubernetes. It listens on port 8080, with one health probe, `/health`, for liveness and readiness.

```bash
docker build -t transactional-system .
docker run --rm -p 8080:8080 \
  -e DATABASE_URL=postgres://postgres:ghk@host.docker.internal:5432/postgres \
  -e AMQP_URL=amqp://ghk:ghk@host.docker.internal:5672 \
  -e JWT_SECRET='change-me-to-a-secret-of-32-chars!' \
  transactional-system
curl -f http://localhost:8080/health
```

The runtime kernel chooses its event broker when it starts: `GHK_BROKER` if set, otherwise the broker whose variables are present, otherwise `stack.messaging`.

| Cloud | Broker | Variables |
|---|---|---|
| AWS | Amazon MQ for RabbitMQ | `AMQP_URL` (the broker's `amqps://` endpoint) |
| GCP | Pub/Sub | `GHK_BROKER=pubsub`, `PUBSUB_PROJECT_ID`; the token comes from the workload identity |
| Azure | Service Bus | `GHK_BROKER=servicebus`, `SERVICEBUS_NAMESPACE` (managed identity). The adapter is generated only with `stack.messaging: "servicebus"` |

The full list of variables and the per-cloud services are in the [deployment guide](https://github.com/FennerEduardo/gherkin-ai-cli/blob/main/docs/DEPLOYMENT.md).

## Regenerate

```bash
npm install -g gherkin-ai@3.2.1
ghk lint -f features/transactional-system.feature
ghk generate -f features/transactional-system.feature
ghk converge -f features/transactional-system.feature     # specification-to-code convergence
```

Regeneration replaces only files that are unchanged since they were generated. An edited file is kept, and the new version is written next to it as `<file>.ghk-new`. Review the diff before committing.
